# GitSomething 1.0.0-beta.2

Windows x64 release candidate prepared October 17, 2026. This candidate is not yet published and is not a stable 1.0 release. The published beta.1 release and its assets remain unchanged.

## Clone GitHub repositories into a workspace

Home's GitHub repository rows now offer **Clone & open**. Choose a parent folder, and GitSomething creates a new child folder with the repository's name, downloads its Git history, checks out the default branch, and opens the real local workspace. Successful clones are added to **Recents**. The separate **GitHub** link still opens the repository in the system browser.

The clone uses the existing native GitHub sign-in and libgit2. The access token stays in the Rust backend and operating system credential store. The Glass Box records the equivalent `git clone` command, transfer and checkout progress, and the result; the app does not execute a Git shell command.

Cancelling the native folder picker leaves the filesystem unchanged. Existing files, folders, and links at the destination are refused rather than overwritten. If a clone fails after its folder is created, GitSomething preserves completed files and reports the error. It does not recursively delete a partial clone or silently reuse its directory. Choose another parent folder to retry, or inspect the saved folder and use **Open repository** if it is usable.

Already downloaded the project? Use **Open repository**, or select its saved entry in **Recents**. A GitHub repository list is a list of remote projects; opening an existing local copy does not require downloading it again. [GitHub sign-in and cloning guidance](https://github.com/imranelak1/GitSomething/blob/main/docs/GITHUB_AUTH.md#clone-a-github-repository) explains the flow.

## Windows candidate

The candidate targets Windows x64. The intended package names are `GitSomething_1.0.0-beta.2_x64-setup.exe` for the current-user NSIS installer and `GitSomething_1.0.0-beta.2_windows-x64.exe` for the standalone application executable. The standalone executable requires an existing Microsoft Edge WebView2 runtime; an installer may need internet access to obtain WebView2 when it is missing.

Windows executables are **unsigned**. Windows may display an unknown-publisher or SmartScreen warning. Candidate packaging, asset hashes, and release readiness must be checked before publication. No signed Windows, macOS, Linux, or ARM64 package is included in this candidate's scope.

## Current limits

- Cloning is available in the desktop app for GitHub.com HTTPS repositories through the connected account. Account permissions, organization policies, and SSO restrictions still apply. GitLab, self-hosted providers, arbitrary clone URLs, and SSH clone entry are not included in this flow.
- The clone creates a new child directory named after the repository. It does not overwrite existing destinations, offer an in-place retry, automatically resume a partial clone, or remove a partial folder. Inspect preserved data before deciding what to keep or remove.
- Submodules are not initialized. Git LFS objects are not downloaded, and external Git filters are not run; LFS-managed content may remain pointer files. Use another suitable Git tool for these steps.
- Hunk/line staging, three-way conflict resolution, worktrees, submodule management, and interactive rebase remain unimplemented. History drags preview relationships without rewriting commits. Complete merge/rebase conflicts with another tool.
- Pull requires a clean fast-forward. Destructive resets and force pushes are unavailable. Text diffs require UTF-8 and are limited to 2 MiB per file.
- GitHub search, visibility counts, and sorting apply to loaded repositories; **Load more repositories** retrieves another page. Browser previews use demonstration data and cannot access native folders or clone repositories.
- Recovery after partial publication remains manual. This clone feature does not change hosted repository creation or add a publication recovery workflow.

## Verification

All **73 frontend unit tests**, **42 Rust tests**, Rust formatting, strict Clippy, the locked Windows NSIS build, and **22 production browser groups** passed. The browser checks use explicit IPC fixtures and cover cancellation, duplicate prevention, existing-folder and native failures, retry, account changes, workspace opening, Recents, and terminal logging.

The actual packaged **1.0.0-beta.2** application passed **10 native checks**, including a real clone of the public GitSomething repository, clean checkout, default-branch/upstream metadata, transfer and checkout progress in Glass Box, existing-destination refusal, watcher refresh, and Recents. The existing approved GitHub connection was preserved. Runtime, console, security, CSP, and cleanup error counts were zero. Only the folder-picker response was supplied by a fixture; Git, auth, filesystem, and event operations were real. No private account/repository metadata or native screenshots were recorded.

Actual private-repository cloning, native picker interaction, installer installation/uninstallation, and live provider publication/pushing remain unverified. Credential destination and failure handling have unit coverage; those results do not establish live private cloning. See [verification](https://github.com/imranelak1/GitSomething/blob/main/docs/VERIFICATION.md) for the recorded boundaries and evidence.
